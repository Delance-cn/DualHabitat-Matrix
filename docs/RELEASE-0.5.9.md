# DualHabitat Matrix 0.5.9

0.5.9 一件事：下载线路默认自动测速选最快。0.5.8 的安装包原样保留，没有覆盖。

## 加了什么

- **下载线路默认走「自动测速」**：之前镜像要自己去「高级 → 更新」手填，不填就裸直连。现在 `updateMirror` 是三档语义，软件本体、NapCat、ffmpeg 三条下载链路统一：
  - **留空（默认）= 自动**：下载前对直连和内置镜像（ghproxy.cn / ghfast.top / gh.ddlc.top）并发发一个 1 字节的探测请求（`Range: bytes=0-0`，最多等 4 秒），可用的里面挑最快的，日志里写明「线路测速：直连 1117ms · ghproxy.cn 1949ms · … → 用 xxx」。哪条线路挂了会在测速里自动淘汰；国内直连恢复时直连也能赢。
  - **填 `off`** = 强制直连，不碰镜像。
  - **填 URL** = 固定走这条镜像（0.5.8 的老用法不变）。
  - 版本查询（GitHub API）始终直连，不走镜像。
- 下载失败的提示按档位给建议：自动档提示「重试会重新测速换线」，直连档提示可填镜像。
- 「高级 → 更新」两个字段的标签和说明改为「下载线路」，写明三档语义；NapCat 安装、本体升级的确认框文案同步。

## 验证

- `desktop/scripts` 18 个测试文件 42 用例全部通过。
- 用与线上一致的探测逻辑实测 v0.5.8 资产：直连 1117ms / ghproxy.cn 1949ms / ghfast.top 1354ms / gh.ddlc.top 429 被淘汰 → 自动选中直连；换网络环境时结果会随之变化。
- 三条下载链路（本体安装包、NapCat Shell 包、ffmpeg）全部接入同一套选线逻辑。
