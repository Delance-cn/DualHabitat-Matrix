          接别的微信 Hook 项目？看这里
          

            
GitHub 上活跃的微信 Hook 项目（wxhelper、WeChatFerry、WeChatPadPro 之类）各有各的回调格式，
              这里用「数据格式」那三档把它们接起来：

            
    
              
  • OneBot v11：输出标准 post_type=message 事件，NoneBot2、Koishi、AstrBot 这类框架直接能收，不用改代码。
    • 
              
  • 自定义模板：自己写 JSON 骨架，插入 {{from}} {{text}} 等字段，按目标项目的文档拼接。
    • 
              
  • 通用 JSON：固定字段 event / at / bot / from / text / kinds，自己写个小服务最省事。
    • 
            

            
推送是「发出去就不管」：对端 2xx 算成功，失败只记日志不重试，不会把消息卡住。

            

              通用 JSON 示例：

              {"event":"message.received","at":"2026-10-20T03:12:00.000Z","bot":"xxx@im.bot","from":"wxid_abc","text":"你好","kinds":"文字"}

    前台客户端

          保存后怎么生效
          
    
            
    点「保存工具开关」会自动重写模型配置并重启在跑的 BOT（几秒空窗，正在回的消息会中断）——
              不用再手动重启。BOT 没在跑就下次启动生效。
    
            
    「电脑操作」一组就是「可以干活」模式：勾了机器人才能读写本机文件、跑命令；
              全关就是纯聊天。它同时管主人档和聊天档。
    
            
    微信那边的工具面不走这里：它只有「收发消息 + 看图」，由微信 Hook 决定。
    
          
    
        
    
      
    

      
    
        
    
          
    语音库与 TTS
    
          发语音有两条路：库里现成的音频（qq_send_voice），或现场合成（qq_say）
        
    

        
    
          
    
            
            
          
    
          
    
            
            
          
    
          
    
            
            
          
    
        
    
        
    Auto 顺序：Edge 在线（默认晓晓）→ 失败自动换 慧慧（zh-CN-HuihuiNeural）→ 再失败落 Windows 离线（本机 Huihui）。超过最长字数会按句子边界截断，并在返回里标明。
    
        
    
          自定义 TTS 引擎（+ 添加：GPT-SoVITS / Bert-VITS2 / 任意命令）
          
    
            
    命令模板只认两个占位符：{textFile} = 待合成文本的 UTF-8 临时文件，{out} = 要写出的音频文件。故意不提供 {text} —— 文本来自聊天内容，直接拼进 shell 等于开放命令注入。例：edge-tts --file {textFile} --write-media {out} --voice zh-CN-YunxiNeural
    
            
    
              
    
                
                
              
    
              
    
                
                
              
    
              
    
                
                
              
    
              
    
                
                
              
    
            
    
            
    
              
              
            
    
            
    
          
    
        
    
        

        
    
          
    
            
            
          
    
          
        
    
        
        

        
    
          
    
            语音库
            
            
            
            
            
          
    
          
    
        
    

        
    
          这是什么 / 怎么填
          
    
            
    「语音库」= config.socialV2.voice.dir（默认 audio/）目录。模型用 qq_send_voice 只能从这里取文件发语音；这里可以直接上传、试听、删除。
    
            
    「TTS」= 模型不想找音频时，用 qq_say 把想说的话现场合成语音（工具开关「语音」组里的「开口说话」）。引擎和嗓音在这里配，改完自动保存并重启在跑的 QQ BOT。
    
            
    SSML：文本可以是完整 <speak> 文档，或带 <break time="300ms"/> 这类片段。注意 Edge 免费端点不接受停顿/重读等标记（会被拒），要这些效果选「Windows 离线」最稳。

    人格
    
          来自 roles/ 目录，按平台各存一份
        
    

        
    
          
          
          按下面「角色卡注入频率」注入 —— 改完人格会立刻重新注入一次；换角色会自动重开会话。
          微信这份只在建会话时注入一次；换角色会自动重开会话。只改内容不用重开。
        
    

        
    
          
    
            
            
            群里说话用哪个方案（改完要重启桥接）
          
    
          
    
            
            
            会话列表里显示的名字

    链接手机
    
        
    把手机上的通知转给电脑：短信、微信、QQ、快递取件码都行。手机端装一个转发 App，把这里的地址填进去就通了。
    
      
    

      
    
        
    
          
    接收开关
    
          —
        
    

        

        

        
    
          
    
            
            
            提示「端口被占用」就换一个，比如 3211。
          
    
          
    
            
            
    
              
              
            
    
            地址里带着它。同一个 WiFi 下别人不知道口令就塞不进来。
          
    
        
    

        
    
          
          
        
    

        
    
          Windows 第一次会弹「是否允许访问网络」，点允许。没弹、或者手机连不上，
            用管理员身份开一次 PowerShell 跑下面这行，然后把电脑和手机都连回同一个 WiFi 再试。
          
    
          
    
            
          
    
        
    
      
    

      
    
        
    
          
    填到手机上的地址
    
          手机和电脑必须在同一个 WiFi（同一个路由器）下
        
    
        
    
          
    启用后出现二维码
    
          
    
            
    还没启用
    
            
              手机相机扫左边这个码 → 打开一页配置说明 → 照着复制进去。打不开就把上面第一条地址手动敲进手机浏览器。
            
          
    
        
    
      
    

      
    
        
    
          
    三步装好
    
          推荐 SmsForwarder：开源、不要 root、规则能按 App 和关键词过滤
        
    

        
      
          
    1. 
            装 App
            手机浏览器打开
              SmsForwarder 发布页，
              下最新那个 .apk 装上（会提示「未知来源」，允许一次）。
          
      2. 
          
    2. 
            给权限
            打开 App → 按它首页的引导，把通知使用权打开（系统设置里叫「通知使用权」或
              「Notification access」）。要转短信的话再给短信权限。
          
      3. 
          
    3. 
            建通道 + 建规则
            「发送通道」→ 新增 → 选 Webhook：地址填上面那条、方法 POST、
              内容类型 application/json、请求体粘贴下面这段。
              然后「通知转发」→ 新增 → 勾上要转的 App（微信/短信/QQ…）→ 通道选刚建的那个。
          
      4. 
        
    

        
    
          
          
    
          
            {{...}} 这些是 App 里的变量，点它输入框旁边那排按钮插进去最保险 ——
            变量名以你装的版本显示为准。只填内容也行：请求体直接写 {{通知内容}}，这边照样收。
          
        
    

        
    
          
          
          
        
    

        
    
          用 message-mirror 或者自己写脚本？
          
    
            
    message-mirror（GitHub 上搜同名项目）：它默认就发
              {app, message_body, type}，把地址填进去即可，请求体不用改。
    
            
    自己写：POST 到同一个地址，认这几个键名 ——
              内容 text / content / message_body / body / msg / message，
              来源 from / sender / title / contact，
              App app / packageName / package。纯文本直接当内容。
    
            
    
          
    
        
    
      
    

      
    
        
    
          
    最近收到
    
          最多留 60 条。同一个 WiFi 下真收到了，这里会立刻多一行
          
          
        
    
        
    还没收到过
    
        
    
          
          
          
        
    
        「本机模拟」只验证电脑这边收得下、显示得出来，不能证明手机到电脑这段网络通。
          「试一下模型那条路」只看桥接在不在、管理员 QQ 配没配 —— 模型那边会收到一条真的后台提醒。
      
    
    
    

    
    
    
      
    
        
    扩展
    
        
    所有对外接口和插口聚合在这：入站 Webhook、出站事件推送、发送 API、插件与 MCP、模型接入。
    
      
    

      
    
        
    
          
    入站 · 通知枢纽
    
          
        
    
        
    POST / GET 这个地址，机器人就把文字转发到 QQ / 微信 / 推送渠道 —— 手表、脚本、自动化工具、快捷指令都能接：
    
        
    
          
          
        
    
        
    口令就是路径最后一段；换口令在「消息与任务」页的通知枢纽卡。发送 API 端口就是本软件的端口。
    
      
    

      
    
        
    
          
    入站 · 手机页
    
          
        
    
        
    安卓装 SmsForwarder 或 message-mirror，把手机通知 POST 到 http://<电脑局域网IP>:<端口>/hook/<口令>；扫码配置在「链接手机」页。
    
      
    

      
    
        
    
          
    出站 · 事件推送
    
          机器人把收到的消息、发出的回复主动 POST 给你配的 URL
        
    
        
        
    
          
          
        
    
        
    
          
          
        
    
        
    
          
          
        
    
        
    
          
          
          
        
    
        
    推送体：{ event: 'message'|'reply', time, data: { platform, chatId, text, … } }，鉴权头 x-dhm-secret。QQ 侧保存后自动重启生效；微信侧下条消息起生效。
    
      
    

      
    
        
    
          
    发送 API
    
          外部程序让机器人发内容（端点详情在下方接口手册）
        
    
        
    sendMessage（文字）/ send-image（图库图片）/ say（现场合成语音条）/ send-sticker（表情）—— 全部走白名单、静默与限频闸门，和聊天里的机器人一个纪律。

    模型接入 · OpenAI 兼容壳
    
          
        
    
        
    任何 OpenAI 兼容的工具（Chatbox / LobeChat / Continue / OpenAI SDK…）把 baseURL 填 http://127.0.0.1:4610/v1 、API key 填下面这串就能用 —— 走的是机器人同款模型池，带故障转移。

    本地 Agent 工具（函数调用）
    
          
        
    
        
    给主人档和兼容壳一组真能干活的工具：list_directory / read_file / write_file / execute_command / search_files。只对主人（QQ 的 ownerQQ / 微信的 ownerId）生效，群聊档永远没有。
    
        
        
    
          
    
            
            
          
    
          
    
            
            
          
    
        
    
        
    
        
    
          
          
        
    
        
    
          安全边界（必读）
          
    
            
    路径围栏：所有读写都解析到沙箱内，..、域外绝对路径、Windows 设备路径、UNC、符号链接/junction 绕行全部拒绝。
    
            
    命令黑名单：rm -rf / del /f /s /q / format / diskpart / shutdown / reg delete / git clean / git reset --hard / curl | sh 等直接拒绝。但命令不是文件沙箱：cwd 固定在沙箱根，命令仍以当前用户权限运行，能写到围栏外、能联网。要真隔离请用 Windows Sandbox / 容器。
    
            
    超时 / 输出：默认 30 秒，超时杀整棵进程树；stdout+stderr 合计上限 128KB。
    
            
    身份：MCP 协议本身不带发送者，所以闸门在路由侧 —— QQ/微信只有 owner 私聊能进 closed-agent（qq-work），兼容壳是 Bearer key。配置里一个主人 ID 都没有时，工具整体拒绝服务。

          为什么不直接打包进安装包
          
    NapCat 约 200 MB、ffmpeg 约 200 MB，全部打包会使安装包增至 1.6 GB，而多数用户仅需其中一个。点击即可从官方发布页下载并安装到用户目录，安装后路径会自动写入配置，无需手动填写。
    
          
    国内直连 GitHub 基本下不动，下载卡住时会提示。下好了本地 zip 的话，用上面的「从本地 zip 装」直接装，效果一样。

    插件
    
          放在桥接根目录 plugins\ 下的 .js，QQ 和微信都能用
        
    
        
    
        
    
          
    
            
    
              
              
            
    
            
    
              
              
            
    
          
    
          
    
            
            
          
    
          
    
            
            
            
            
          
    
          
    保存后立即热重载（桥接在跑时；没在跑就下次启动自动装载）。插件拥有与桥接相同的本机权限 —— 只装信得过的代码。
    
        
    

        
    
          
          
          
        
    
        
    
          插件怎么写？
          
    
            ESM 模块，default 导出 { name, description, commands: [{ name, usage, description, run }] }。
            run 拿到 ctx（ctx.reply(text) 回消息、ctx.platform、ctx.from、ctx.config）和参数数组。
            示例见 plugins/example-hello.js（装好就能发 /hello、/roll 试试）。
            插件拥有与桥接进程相同的本机权限，只装信得过的代码。
          
    
        
    
      
    

      
    
        
    一键自检
    实际发送一次请求，验证是否正常返回
    
        
    不是测「能不能连上」，是测「模型会不会回话」—— 端点通但 key 错、模型名错，这里都会露出来。
